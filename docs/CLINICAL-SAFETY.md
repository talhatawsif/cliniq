# Clinical safety: hazard log

ClinIQ is a portfolio prototype on synthetic data. It is not a medical device and has had no clinical safety review. This log
is the kind of document a real deployment would start from: what could go wrong, what the product does about it, and what
evidence is in the repository. "Evidence" names a test or a UI control that exists today. Residual risk is stated, not hidden.

| # | Hazard | Cause | Possible effect | Mitigation in the product | Evidence | Residual risk |
|---|---|---|---|---|---|---|
| 1 | A negated finding is recorded as present ("denies chest pain" becomes chest pain) | NLP misses a negation cue | A condition the patient does not have enters the chart | Only mentions with no negation, family, historical, hypothetical or uncertain flag are written; ConText rules include Australian forms (nil, NKDA, denies); everything written is *unconfirmed* and reviewed | `services/nlp/test_extract.py` (C1–C16); `src/lib/pipeline/build.test.ts` (W6); `tests/e2e/pipeline.spec.ts` | A cue the rules do not know is missed; the reviewer is the last defence |
| 2 | A finding is coded to the wrong SNOMED CT concept | Term matches several concepts; abbreviation ambiguity | Wrong problem on the list | Deterministic ranking, no code under 0.5 confidence, up to four alternatives, a rationale, and a human decision before the code is confirmed | `src/lib/terminology/terminology.test.ts`; `docs/validation/terminology.md`; review changes code in `tests/e2e/pipeline.spec.ts` (W8) | Only the acceptance terms are verified against the server; other terms depend on the ranker |
| 3 | An auto-extracted finding is treated as fact | Unconfirmed data reaches decision support or an export | Alerts or documents built on an unverified diagnosis | Unconfirmed Conditions are excluded from CDS cards and the AU Patient Summary and carry the badge "Auto-extracted — pending review" | `src/lib/pipeline/build.test.ts` (W11); `src/lib/ps/build.test.ts`; `src/lib/cds/rules.test.ts`; `tests/e2e/pipeline.spec.ts` (W10) | A new consumer of Condition data that forgets the rule |
| 4 | A result or finding is attached to the wrong patient | HL7 identifier matches nobody or several people; a note is run against the wrong chart | Data on the wrong record | HL7 results are matched only by IHI and only when exactly one patient matches (never created); a pasted note stores the patient with it; the patient banner is repeated in the JSON drawer and on every review card | `src/lib/hl7v2/hl7v2.test.ts` (H1, H2); `tests/e2e/smoke.spec.ts` (drawer repeats the banner); `tests/e2e/pipeline.spec.ts` (review card shows the banner) | Two patients sharing an IHI in the source data would be refused, not guessed; a wrong IHI on the message is still wrong |
| 5 | Duplicate or corrected pathology results are mishandled | A lab resends a message or sends a correction | Double counting, or a stale value left standing | Resource ids derive from the filler order number and test code, so resends and corrections update one resource; a duplicate control id is acknowledged without a write | `src/lib/hl7v2/hl7v2.test.ts` (H11, H12); `tests/e2e/hl7.spec.ts` (version 2 on correction) | A lab that reuses a filler number for a different order |
| 6 | A wrong time is stored | A timestamp has no offset | A result appears on the wrong day or time | No offset anywhere means the time is dropped and only the date kept, never guessed | `src/lib/hl7v2/hl7v2.test.ts` (H7) | Date-only precision for such messages |
| 7 | "No allergies recorded" is read as "no known allergies" | Both look like an empty list | A patient is assumed safe to prescribe for | The two states are different in the banner and the table; an empty section in the patient summary says "no information" with an empty reason, not a "none known" claim | `src/lib/fhir/clinical.test.ts` (allergyStatus); `tests/e2e/smoke.spec.ts`; `src/lib/ps/build.test.ts` | Users who do not read the banner |
| 8 | A calculated value is stale or applied to the wrong person | eGFR from an old creatinine; a child or a person of unknown sex | A misleading kidney function or care-gap card | The card states it comes from the latest creatinine; under-18s and unknown sex get "not calculated"; deceased patients get no cards; results show their dates | `src/lib/cds/rules.test.ts` (E1–E14) | The card does not show the age of the creatinine on its face |
| 9 | The chart assistant states a value that is not in the record | A language model makes something up | Wrong value taken as fact | Every sentence must cite facts from this patient and every number and date must appear in a cited fact, or the sentence is removed and the UI says so; model answers are labelled "AI-generated — verify against the record" | `src/lib/assistant/assistant.test.ts` (A4, A5, A13); `docs/assistant-eval.md` | A true value paired with a wrong interpretation word passes the filter |
| 10 | The assistant gives clinical advice | A user asks what to prescribe, stop or conclude | Advice with no clinical governance | A deterministic pre-filter refuses advice, dosing, diagnosis and prognosis requests with no model call | `src/lib/assistant/assistant.test.ts` (A8); `tests/e2e/assistant.spec.ts`; evaluation d1–d3 | Rephrasing can evade a pattern list |
| 11 | A prompt injection in a note changes the assistant's behaviour | Note text contains instructions | The assistant leaks its prompt or follows the note | Note text is passed as quoted untrusted data; a canary string in the prompt blocks any reply that leaks it | `src/lib/assistant/assistant.test.ts` (A7); evaluation i1–i3 | A novel injection that does not leak the canary |
| 12 | A read-only SMART session writes to a record | The app is launched from an EHR or sandbox | Unwanted change to another system's data | Every non-GET request is refused with 403 `smart-read-only`; the FHIR client refuses to POST; the launching server only ever receives the user's token | `tests/smart/smart.spec.ts`; `src/lib/fhir/smart-client.test.ts` | Needs a deliberate reconfiguration to remove |
| 13 | The chart shows an empty list when the server is down | FHIR server asleep or unreachable | Missing history looks like no history | A failed read shows "The FHIR server is not responding" and never an empty chart | `src/lib/fhir/client.test.ts` (error kinds); `src/components/FhirNotice.tsx` | A partial failure that returns some resource types and not others |
| 14 | A chart read right after a write is stale | HAPI reuses search results for 60 s | A just-confirmed finding still looks unconfirmed | Every app read sends `Cache-Control: no-cache` | `tests/e2e/pipeline.spec.ts` (confirmed on the chart straight after the decision) | Other FHIR servers may cache differently |
| 15 | Someone without a session reads or writes records | Open endpoints | Unauthorised access | Pages redirect to sign-in, APIs return 401, audit and quota tables are unreadable with the public key, writes are audited | `tests/e2e/security.spec.ts`; `docs/SECURITY.md` | One shared demo account; no real identity |
| 16 | The same finding is recorded twice | Rerunning a note | Duplicate problems | Conditional create on an identifier from note and code; findings already on the problem list are skipped | `tests/e2e/pipeline.spec.ts` (W5) | Same condition coded differently in two notes |
| 17 | A unit is misread (HbA1c % versus mmol/mol) | Two valid units | A wrong clinical judgement | Both are shown for HbA1c; units are normalised through UCUM text | `src/lib/fhir/analytes.test.ts` | Other analytes with several units |

## Not covered

No clinician has reviewed this log. It has no hazard rating scheme, no post-market monitoring, and no assessment against the
TGA's rules for software as a medical device or any clinical decision support exemption. See the "Path to production" section
of the About page.
